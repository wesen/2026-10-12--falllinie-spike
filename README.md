# Falllinie native terrain / print-shader spike

C++17 + SDL2 platform layer, GLES3 renderer loaded through SDL_GL_GetProcAddress.
The original bounded graphics qualification now also has a **first playable
source-based downhill slice** (`--play`). This is not the complete game port;
reactive audio, full tricks/combos, incremental streaming and second-screen game
logic remain unfinished. The static graphics checkpoint below remains reproducible.

`FALLLINIE-GLES-001`. Original SHA256:

## Build / deploy

Desktop (SDL2/GLES3 headers):

```
node scripts/generate-gl-loader.cjs
cmake -S . -B build && cmake --build build
ctest --test-dir build --output-on-failure
./build/falllinie-spike --seconds 10
```

ARM64 (Docker, Node, working SSH authentication):

```
bash scripts/build-device.sh
bash scripts/deploy-device.sh
```

The cross-build uses a pinned Debian container, ARM64 headers/compiler, and the
actual target SDL library; binaries/libraries are ignored, not vendored. ROCKNIX's
GLES library is a Mali hook shim, so GL functions are loaded after context creation.
Actual target: ES 3.2, Mali-G52, GLSL ES 3.20. Deployment adds a dedicated port launcher
at `/storage/roms/ports/falllinie-spike.sh`; it does not modify Sway configuration.

Device command, in `/storage/apps/falllinie-spike`:

```
./falllinie-spike --place --seconds 12 --cell 2 --render-size 512x384 \
  --capture-dir captures/marker --receipt marker.json
```

Run without `--seconds` for an indefinite fixed-camera inspection. F10 or
retrogame_joypad SELECT+START (indices 8+9) quits. F3 cycles final, luminance,
key ink, material ID, spot ink and depth views; C cycles six palettes. Debug and
palette controls no longer occupy source gameplay buttons. The joystick name is logged.

Options: `--seed`, `--cell -1..64`, `--cells 1..7`, `--render-size WxH`,
`--debug-view 0..5`, `--palette 0..5`, `--frames`, `--assets`, `--resize-check`.
Scene and print targets have the same resolution; nearest presentation scales to
1024x768. Print pitch scales as 4.4×width/1024 so final dot spacing is intentional.

## Fidelity and GLES portability

The four archived shader files remain byte-identical to the original extraction.
**One deliberate compile-time override** declares the print depth sampler `uD`
`highp`. The original implicit sampler precision on Mali produced strong false
horizontal depth edges; explicit highp removes them and restores the 0250 marker.
`--source-sampler-precision` reproduces the unmodified declaration for A/B testing.
No shader algorithm or noise function has been replaced.

Original digit atlas: generated by the source's `makeGlyphs()` in Chromium after
Archivo font readiness, then PNG → RGBA BMP (SDL's built-in loader). Assets record
that original canvas output, not substitute typography. The browser reference
removes analytics and animation scheduling, fixes seed/camera/cells and excludes
rider/props/audio. Scripts and provenance are in the sibling ticket investigation.

`node scripts/generate-cpu-fixtures.cjs` reproduces 268 scalar/normal/metadata
cases (including 178 kicker/cliff samples), 5 wrapping hashes, 12 RNG values and
6 original mesh vertices/normals from the frozen HTML. Per cell: 14,873 vertices,
87,768 uint32 indices and 44-byte stride; the original 0.4 m cell overlap is retained.

Browser (ANGLE/Intel) vs Mali marker comparison: lower-half ink IoU 0.969, mean
channel error 2.55/255, 0.353% pixels with max channel difference >16. Whole-image
bit parity is **not** claimed: original sin-based sky/noise hashes vary across GPUs.
The implicit-depth legacy version had 41.9% large-error lower-half pixels.

## First playable milestone (after the static graphics checkpoint)

`--play` now enables source-based downhill physics, charged jumps, original
source-generated rider poses, following camera and moving terrain patches.
The device port launcher defaults to this mode. `--autoplay` is synthetic input
for recording; it is not a substitute for physical playtesting.

Ground: stick/dpad left/right steer; UP tucks, DOWN brakes; hold/release button 0
(A/SPACE) to jump. Air: left/right spin, up/down flip, release to auto-complete.
START/P/ESC pauses; R or SELECT+Y starts a new seeded run; F10 or SELECT+START
quits. SELECT/F2 toggles developer data. HUD displays speed, distance, landing
points and contextual controls using the original embedded IBM Plex Mono font.

Historical limitations at the first-playable checkpoint (see FALLLINIE-GAME-002
for the subsequently merged source systems, not a complete-parity claim):
Spins/flips and landing alignment follow the source, but full grabs/ubers, runtime
IK, combo/repetition scoring, original bail animation, objects, trails and reactive
audio remain unfinished. Crouch uses three baked original poses. Cell transitions
currently rebuild a four-cell patch synchronously. This is a playable port slice,
not a claim of complete game parity. Current diary: native ttmp ticket FALLLINIE-PLAY-001.

## Native developer overlay (source gameplay)

`--dev-overlay` enables gameplay (`--play`) and shows the panel from the title/demo.
For parent qualification without injected input, use `--dual-screen --dev-overlay`
with the existing launcher/render-size settings. It does not start the run or open
audio until the usual A/START/ENTER/SPACE drop-in. The port launcher forwards flags:
`bash scripts/falllinie-spike.sh --dev-overlay`. The launcher explicitly selects
no-vinyl playback; append `--source-vinyl` to restore the authored mix.

Current raw pad map: A0 jump, B1/X2 boost, Y3 in the new-run chord,
L1/R1/L2/R2 (4–7) grabs, SELECT8 developer overlay, START9 pause/start,
dpad13–16. Keyboard: WASD/arrows steer/drive, SPACE jump, SHIFT/B boost,
J/K/U/I grabs, R new run, F2 overlay, F3 diagnostic views, C palettes, M mute,
P/ESC pause, F10 quit.

- SELECT/F2 toggles on the press edge; holding does not repeat. Available in title,
  run and pause; drawn only on the top/chase output, never first-person.
- SELECT+Y requests a new seeded run (not from title); either press order works.
  SELECT+START quits with precedence, without new-run or same-snapshot overlay effects.
- An immediate standalone SELECT press necessarily shows/hides the panel briefly
  if Y/START joins on a later frame. That chord restores the pre-SELECT visibility;
  SELECT release clears ownership. An independent F2 press cancels that restoration
  token, so a later chord cannot undo an unrelated keyboard toggle.

The readable 1024x768 panel uses the original font, 18 bounded rows and one extra
quad batch, not fullscreen per-glyph passes. Text and geometry refresh about 4 Hz
(or on toggle/resize); the disabled path never reads audio diagnostics or formats
text. The main thread captures numeric snapshots without changing simulation or
consuming additional events. It displays:

- Rolling CPU loop FPS/interval (up to 120 completed frames), **not physical
  presentation rate**, and previous completed frame input, physics, player,
  streaming (a player subset), top/bottom submit/swap and pacing wall times.
- Rider state/position/speed/air/charge/slowmo/ticks, seed and generation;
  resident terrain/object cells, terrain job activity/cell, visible vertex/index
  counts, snow/trail counts, internal/output size and camera-relative origin.
- Audio backend, actual rate/buffer, worker/direct mode and vinyl preference.
  Buffered playback shows callback wall mean/max/budget and measured thread CPU
  mean, PCM depth/target/observed low/high, produced/delivered frontiers, starvation
  callbacks/missing frames, DSP wall/CPU mean and block-budget exceedances.
  **Callback wall-budget misses and PCM starvation are NOT driver XRUN counts;
  producer block-budget exceedances are NOT callback failures.** Direct mode
  retains the original callback/command/voice rows. Full counters are logged at
  exit. Closed audio/unavailable clocks are n/a; counters are cumulative.
- GPU elapsed/utilization and CPU utilization are explicitly **n/a**. The separate
  CSV/GPU profiler remains independent; no utilization estimate is invented.

### Buffered native audio and qualification

Live playback defaults to one same-process DSP worker and a preallocated stereo
float SPSC ring. SDL's buffered callback only copies available PCM, zero-fills
shortage and records numeric counters/clocks; it never synthesizes, allocates,
locks, waits or notifies the producer. `--audio-mode direct` explicitly restores
the synchronous DSP callback for diagnostics; failure never selects it implicitly.
Offline rendering uses the same DSP math, mutually exclusive with live owners.

`--audio-buffer N` requests a power-of-two SDL buffer from 256 to 4096 frames.
Executable/API default is 512; the handheld launcher requests 1024. The worker
renders 1024-frame blocks and targets `ceil(obtained_frames/1024)*1024 + 1024`
ready frames, not the 8192-frame capacity. At 48 kHz, the usual 2048-frame lead
is about 42.7 ms; a 4096-frame request targets 5120 (~106.7 ms). Actual queued
lead varies with callback consumption. This adds event/mute latency on top of
backend buffering and existing 1024-sample wet latency. The full 2.6-second stereo
IR, 2x49-tap saturation, sorted mixing/stealing and source RNG remain unchanged.

Pause quiesces SDL and acknowledges stopped production, retaining unheard PCM
and freezing the produced musical clock. Resume continues it without sample
skips; mute/restart do not reset the clock. Close joins both owners. Active open
is idempotent (ignores new options); close/reopen is required to reconfigure.
Caller-owned SDL audio initialization survives engine destruction.

Library/executable/offline defaults retain authored vinyl. `--no-vinyl` is a
preference, not a timing fix: generation/filter/RNG state still runs. The launcher
explicitly passes it; last option wins, so `--source-vinyl` restores source mix.
Reproduce matched offline probes with
`python3 scripts/2026/10/13/audio-crackle-isolation/01-build-matched-probes.py`.
It now uses the offline preference API, preserves historical logs/manifest and
writes new evidence under FALLLINIE-AUDIO-003; WAVs/binaries remain ignored.

Host validation: build with CMake and run `ctest --test-dir build-audio
--output-on-failure`. Audio tests cover source numerics/arrangement/allocation,
PCM FIFO/stereo/partial/wrap/shortage, actual worker/callback bit identity,
