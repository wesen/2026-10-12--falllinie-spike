# Evidence boundaries

This is a source-based investigation plus **host functional** validation, not a target performance report. [Design 01](01-measurement-contract-and-optimization-investigation.md) is the authority contract. Parent owns ARM deployment, representative target measurements and final hypothesis acceptance. No shader math/precision, geometry, RNG, simulation or audio changes are proposed as accepted optimizations here.

Historical [AUDIO-003 buffered frames](../../FALLLINIE-AUDIO-003--buffered-native-audio-worker-and-callback-deadline-qualification/scripts/target/buffered/frames.csv): 120s dual384x288, no-vsync/fps60, buffered48k/1024, muted full DSP, vinyl and developer overlay enabled. After 60 warmup frames: 6001 intervals, mean19.7839ms, top renderer wall9.5481ms, bottom8.1037ms, swaps0.8962ms, physics0.1557ms, player0.6613ms **including stream0.0866ms**, pace0.0058ms. The GPU CSV is header-only. These are neither GPU elapsed times nor utilization. 60Hz requires16.6667ms; this historical run has no demonstrated headroom. A source-only or JS probe commit cannot establish a changed graphics budget.

Retained initial evidence is limited to x86 host llvmpipe (`LLVM20.1.2,256bits`) functional checks: 13/13 CTest (the existing12 plus profiler), 9 parser tests, six short GL cases with zero reported GL error, correct pass omission and **POST-RUN UNINSTRUMENTED FIXTURE REPEATABILITY**. The original capture comparison redraws after measurement detachment: it does not establish query-active image equivalence, which is deferred. The review correction passed19 analyzer tests,1 focused profiler CTest and1 fresh8-frame schema2 static host run (no capture); see the [correction annotation](../scripts/evidence/review-corrections.md). See [bounded logs](../scripts/evidence/) and [commands/limits](../scripts/README.md). Host timings are intentionally **not ranked as Mali gains**. Actual A55/Mali-G52 pass distributions, query observer effect, disjoint rate and thermal/frequency conditions: **PENDING**.

## Shader mechanisms (actual preserved bodies)

- [scene_fs.glsl](../../../../../../assets/shaders/scene_fs.glsl),6–10,18–22: terrain/trail fragments run three analytic `rayseg` shadow evaluations (dot/divide/clamp/length/smoothstep), in addition to normal/luminance/distance. Segments are uniform per frame but distances depend on fragment world position. A source fact, **not measured dominance**. Precompute light/segment-only dot products is mathematically tempting; reassociation/precision and degenerate-segment behavior require pixel and source-parity review before any change.
- Same shader,23–50: derivative-based terrain grid/contours, stripe logic and conditional glyph sampling. X-ray palette adds extra grid derivatives; distance/glyph branches change actual workload. Treat palette and camera as experiment controls. Culling/backface enablement can remove visible two-sided geometry; it is not automatically equivalent.
- [post_fs.glsl](../../../../../../assets/shaders/post_fs.glsl),16–47: always one depth and one color sample; non-sky branch adds four depth neighbors and four color/material neighbors: **ten texture reads total** there. Sky branch reconstructs direction via inverse VP, normalize/atan and four noise calls. The existing native adaptation replaces the unstable sky hash with a170-entry uniform lattice unless source hash explicitly selected; it does not remove shape math. Shader text remains unchanged in this work.
- Same shader,10–14,48–61: halftone sqrt/length, optional speed-line atan/hash, grain hash with time each pixel and flash/color mixing. View/resolution/time dependence prevents a blanket static LUT proposal. Existing highp depth portability override stays highp. Source sky hash and sampler switches must remain fixed in comparisons.
- [scene_vs.glsl](../../../../../../assets/shaders/scene_vs.glsl) and [post_vs.glsl](../../../../../../assets/shaders/post_vs.glsl): CPU native renderer explicitly rebases scene projection in loaded source; original shader bodies in assets preserved. No mesh simplification, new culling, RNG substitution or shader precision change is part of measurement implementation.

# Safe reuse and CPU parallelization seams (proposals only)

1. **Terrain/object immutable job**: input `(seed, generation, cell, geometry revision, complete required parameter/feature definitions, cumulative drop prefix)` or worker-owned equivalent deterministic evaluator. Existing `Terrain&` and `World&` are forbidden worker inputs because they mutate caches and have references whose eviction matters. Preserve deterministic local RNG sequence and row/normal neighbor sampling. Worker owns output `CpuMesh`; a bounded completion queue returns `(generation,cell,mesh)`. Main checks generation, requested cell range and duplicate/retired completion before GL upload. Cancellation drops output, does not perturb authoritative simulation RNG. Bound queued meshes/bytes so975MiB with no swap is not stressed. Scheduler must leave measured CPU budget for audio producer; no new priority/affinity knobs.
2. **Snapshot particle/pose preparation**: copy immutable particle/history/rig snapshot after the single authoritative update. Snow adds explicit per-view camera basis; trail includes game-time aging. Completion must match frame/snapshot generation; do not render stale geometry silently to hide missed deadlines. Rider rig already required for camera and shadow uniforms, so moving it off-thread may add a dependency fence; move only independent mesh transform if target CPU evidence supports it. No blocking worker wait inside audio or GL callback.
3. **Precompute once per generation/program**: shader locations, constant tables already mathematically invariant, terrain fixed topology/index patterns, potential rider groups when topology unchanged. Existing terrain templates and stable sky table must be acknowledged rather than reinvented. Each has explicit context/program or seed/cell/version invalidation; no source shader rewrite accepted in this slice.
4. **Per-frame reuse on main first**: trail reuse is simpler than worker fanout. CPU job concurrency does not create parallel GL ownership. Audio DSP worker is already a separate timing/ownership domain; do not share simulation state or audio RNG with graphics jobs. No JS worker/execution-mode fallback is needed to measure this renderer.

# Measurement coverage and next decisions

Implemented scene/post/output GPU passes and whole-view alternative, CPU nested dynamic-prep/upload, bounded availability/disjoint/pending accounting, deterministic **static terrain** fixture, real post bypass, parent runner/analyzer and fake tests. Deliberately **not** added: terrain/object GPU subdivisions, pure HUD GPU scope, draw/triangle/upload byte counters, dedicated context timer, production mesh caches, shader rewrites, worker queues, full-game replay. These are follow-on instrumentation/optimizations only if initial target evidence justifies them. Existing vertex/index/developer diagnostics provide source counts but not emitted per-frame draw counts.

Static fixture omits objects/rider/snow/trails/HUD/streaming/audio and duplicates top camera in lower window. It is suitable for controlled post/scene/output, query observer and view/resolution experiments only. Live autoplay separately preserves single update, head view, streaming and muted full DSP but is not deterministic replay. No freeze-after-autopilot frame count is claimed deterministic because cooperative streaming and time-dependent trajectories can differ.

Before parent chooses an optimization: review candidate lifecycle/context cleanup, run offline ARM build with explicitly approved libs, inspect device state, bounded GL smoke, then balanced query-off/on at matched CPU telemetry. Reject unsupported/disjoint/invalid GPU times; assess cadence and pending/skipped counts. Record actual renderer/extensions/caps, exact source+binary hashes, arguments/order/warmup, actual frequency/memory/thermal boundaries, CPU distributions and audio shortages. Run initial static five-case forward/reverse set, then representative live off/on/on/off. Only then replace preliminary hypotheses with target-backed findings. No60FPS, GPU-utilization or complete-game-parity claim is authorized by the host evidence.
